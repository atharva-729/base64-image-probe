base64-image-probeAn experiment, October 2026

Can a model read a picture it can’t see?

We turned tiny images into strings of letters and digits, pasted them into four language models as plain text, and asked what the picture was. The models had no tools, no code and no vision. Two of them got every single pixel right.

01 The idea

A picture is just a file, and a file can be written as text

When you attach an image to a chat, the model looks at it with a separate vision system. We took that away. An image file is a sequence of bytes, and any bytes can be spelled out with ordinary characters using an encoding called base64. The result looks like gibberish.

The question is whether a model can work backwards from that gibberish to the picture, purely by reasoning. It is like being handed a page of Morse code and asked what the drawing is.

02 The setup

Text in, text out, nothing else

An earlier round used chat apps, and one objection sank it: a chatbot can quietly write code to decode the image and then look at the result. So every run here goes through the API with no tools attached. Whatever a model gets right, it worked out in its own reasoning.

Two shapes and two blocks of random noise. The noise matters most: nobody can guess random pixels, so a model that reproduces them exactly has really decoded the file.

Not all PNGs are equally hard

A PNG can compress its pixels in different ways. GPT-6 Luna decoded both PNGs that store their pixels uncompressed, even at 16×16, and struggled with the ones that use real compression.

Every grid Luna did produce on PNG was pixel-perfect. It finishes correctly, declines, or runs out of tokens; it never returned a wrong grid. That compression explains the pattern is an inference from these eight files.

Decoding is not recognising

Getting the pixels right and knowing what they show turned out to be separate skills.

  • GPT-6 Luna decoded the X exactly from a BMP, then called it “a white diamond on a black background”.
  • It decoded the 7 exactly from a PNG and described “a short horizontal bar with a zigzagging stem”.
  • GPT-6 Sol decoded the 7 with black and white swapped. PNG stores black as 0 and the prompt asked for black as 1, so the trap is partly ours.

The cost is the thinking

The input is a hundred characters. Nearly all the cost is reasoning: a PNG took Sonnet and Sol about a minute and 6–7 cents, against a few seconds and under a cent for the same picture as PBM.

What this is not

This is not a better way to send images to a model. Attaching an image normally is far cheaper and more reliable than any of this. The experiment measures how far a model’s reasoning can go on raw file bytes, and nothing more.

07 The bill and the fine print

What it cost

23 of GPT-6 Luna’s calls hit a token limit and returned nothing. They are billed all the same, and came to $0.19.

Read with care

  • Small counts. Sonnet, Sol and Gemini have one run per cell on two images.
  • Tiny images. These are 20–130 characters of base64. A real photo is hundreds of thousands. Nothing here says the result carries over.
  • Token limits cut both ways. A model that hit its limit did not finish; that is different from being unable.
  • Unequal settings. Each model has a different range of reasoning effort, so each is shown at a setting where it reasons.

Run it yourself

Everything is in the repository: the images, every prompt, every raw reply and the scoring. Replies are cached, so re-running costs nothing unless you add something new.

python make_images.py      # test images
python make_prompts.py     # encodings and prompts
python run_openrouter.py --phase 1 --dry-run   # list calls and worst-case cost
python score.py            # replies -> results.csv
python make_site.py        # this page
